# Recycling RobotArm — 영화관 분리수거 로봇

영화가 끝난 뒤 상영관에 남겨진 음료 컵을 **로봇팔이 부품별로 분리수거**하는 시스템입니다.
컵이 아두이노로 움직이는 컨베이어 벨트를 타고 들어오면, 카메라가 컵을 찾고 로봇팔이 컵을 들어 뚜껑을 떼고 남은 음료를 비운 뒤 각각 알맞은 통에 넣습니다.

> 아직 정하지 않은 내용은 `(TBD)`, 회의에서 미룬 내용은 `(보류)`로 표시합니다.

---

## 1. 왜 만드나

- 영화관 상영이 끝나면 직원이 컵을 하나씩 손으로 분해해 빨대, 뚜껑, 컵, 컵홀더, 남은 음료를 따로 버립니다.
- 반복적이고 지저분한 이 일을 로봇팔이 대신해, 분리수거 정확도를 높이고 직원의 부담을 줄이는 것이 목표입니다.

## 2. 무엇을 하나 (이번 프로젝트 범위)

| 구성 | 역할 |
|---|---|
| 로봇팔 | 컵을 집어 벨트에서 꺼낸 뒤 **뚜껑·빨대 분리 → 남은 음료 비우기 → 빈 컵 버리기** |
| 컨베이어 벨트 | 컵을 로봇팔 작업 위치까지 옮긴다. **아두이노로 구동**하고, 제어 PC의 명령으로 멈추고 출발하며 속도를 바꾼다 |
| 카메라 3대 | CAM 1 상단 웹캠(벨트 전체·컵 분포), CAM 2 로봇팔 카메라(컵 위치·자세), CAM 3 작업 위치 카메라(컵 도착 감지) |
| AI 비전 | 음료 컵(뚜껑 유/무)과 기타 쓰레기를 구분하고, 집을 위치를 찾는다 (5절) |

시연에서 다루는 부품은 **뚜껑, 빨대, 컵(+ 남은 음료)**입니다.

### 시연 시나리오

전체 흐름도: [docs/usecase.puml](docs/usecase.puml) (PlantUML). 흐름도는 로봇팔 동작을 "뚜껑 제거 → 음료 비우기"로 간소화해 두었고, 세부 동작은 실습하며 실험해 확정합니다.

```text
[사용자] 시스템 시작, 컨베이어에 쓰레기 투입
[아두이노] 컨베이어 구동
  ├─ (계속) CAM 1이 컵 분포·밀집도 분석 → 제어 PC가 벨트 속도 결정 → 아두이노가 속도 조절
  └─ (계속) CAM 3이 작업 위치 감시
        컵 도착 → 제어 PC가 벨트 정지 명령 → 아두이노 정지
        CAM 2로 컵 위치·자세 검출 → 로봇팔 기준 좌표 계산
        로봇팔이 컵을 집어 벨트에서 꺼냄
          ├─ 벨트 재가동 → 다음 컵이 오면 다시 정지하고 로봇팔 작업 완료를 기다림
          └─ 로봇팔: 뚜껑 제거 → 액체 수거통으로 이동 → 기울이기 또는 압착으로 음료 배출
                    → 빈 컵을 쓰레기통에 넣기 → 작업 완료 신호 전송
[종료] 컨베이어 정지 → 로봇팔 대기 자세 복귀 → 시스템 종료
```

### 실험으로 정할 것

| 항목 | 고민 내용 |
|---|---|
| 뚜껑 열기 | 로봇팔 1대로 뚜껑을 어떻게 열지 (컵 고정 방법 포함) |
| 빨대 분리 | 뚜껑과 함께 뺄지, 따로 뽑을지 |
| 쓰레기통 | 몇 개를, 어느 위치에 둘지 |
| 장비 배치 | 로봇팔, 상단·작업 위치 웹캠, 컨베이어를 어디에 둘지 |

## 3. 앞으로 하고 싶은 방향 (이번 범위 밖)

이번 발표까지는 구현하지 않지만, 설계할 때 막히지 않도록 염두에 두는 확장 방향입니다.

- **팝콘 통 분리수거**: 음료 컵 외에 팝콘 통과 남은 팝콘도 분리
- **길거리 배치**: 영화관 밖 길거리에도 비치해 환경 미화에 활용

## 5. 기술 스택

### 소프트웨어

| 항목 | 내용 |

### AI 비전 모델 — DTRA v3.1

D(승준)가 개발한 오픈소스 모델(B-spline 기반, MIT 라이선스)을 사용합니다: [5Color/dtra](https://github.com/5Color/dtra) (`v3.1.0` 태그)

#### 학습 방식과 원리

| 원리 | 설명 |
|---|---|
| 적은 데이터로 빠른 등록 | 사물 형태를 뽑는 시각 백본(ResNet)을 고정해 쓰므로, 사진 수천 장 없이 **샘플 몇 장과 자연어 라벨**만으로 물체별 전용 기억 슬롯을 바로 만듭니다. |
| 기존 기억 잠금 | 등록이 끝난 슬롯은 잠가 둡니다. 나중에 새 쓰레기를 추가해도 과거 데이터를 다시 학습할 필요가 없고, 기존 '음료 컵' 기억이 지워지지 않습니다. |
| 배경 제거, 유사도 기준 판별 | 공통 배경·조명은 빼고 물체 윤곽선 차이만 비교합니다. 기준선 안이면 **음료 컵**(뚜껑 유/무, 집을 위치), 기준선 밖의 낯선 물체면 **기타 쓰레기**(통과)로 실시간 판별합니다. |

#### 아키텍처의 특징

- **확장이 쉬움:** 팝콘 통 등 다른 쓰레기도 샘플 몇 장만 새로 등록하면 추가할 수 있습니다.
- **가벼운 실행:** 필요한 슬롯 하나만 켜서 계산하므로 Raspberry Pi 5(ONNX)에서도 실시간으로 동작합니다.
- **연속 작업에 강함:** 로봇팔 카메라 흔들림에 강하고, 컵 하나가 끝날 때마다 상태를 초기화해 연속 작업 중 오류가 쌓이지 않습니다.
- **동작 생성까지 연결:** 집기·기울이기 같은 기본 동작 부품을 공유해 재사용하고, 인식 결과에 맞춰 로봇팔 궤적도 B-spline 곡선으로 끊김 없이 부드럽게 만들 수 있습니다.

> **성능 수치 (개발자 측정치):** 100개 연속 작업 기준 구분 정확도 99.9%, 처리 시간 약 2ms. 이 프로젝트의 컵·카메라로는 아직 측정하지 않았으며, M3 안정화 단계에서 다시 측정해 `docs/experiments/`에 기록합니다.

### 실행 장비

| 장비 | 용도 |
|---|---|
| 로봇팔 Raspberry Pi 5 (ARM64) | 로봇팔 제어, 비전 실행 |
| 제어 PC (노트북) | 메인 프로그램: AI 결과 → 아두이노 명령 전달 |
| 학습 서버 (GPU) | 모델 학습 (계정 확정 후 기록) |
| 개발 PC (Windows 노트북) | 데이터셋 만들기, 코드 작성, SSH 접속 |

장비끼리는 ROS 2(DDS) 또는 다른 가능한 방식으로 직접 통신합니다. 아두이노 연결 방식은 (보류)입니다.

### Docker

- 로봇팔 이미지는 `robot-delivery`의 `team/arm` 이미지(`ros:humble-ros-base` 바탕, arm64·amd64)를 이어서 씁니다.
- `network_mode: host`, `ROS_DOMAIN_ID=4`, `--privileged` 대신 필요한 장치(로봇팔 USB 시리얼, 카메라)만 연결합니다.
- `stop_signal: SIGINT`로 `docker stop`도 Ctrl+C처럼 처리해 대기 자세 → 토크 끄기 순서로 안전하게 멈춥니다.
- 이 프로젝트용 이미지 이름·서비스 구성은 (TBD)입니다.
